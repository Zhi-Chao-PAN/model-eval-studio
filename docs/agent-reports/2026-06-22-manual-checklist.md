## 需要人工验证的流程

1. 打开本地开发环境：`pnpm dev`。
2. 登录系统。
3. 新建或打开一个任务（任务信息步骤填好基础信息）。
4. 至少准备两个模型（看板识别步骤或手动添加）。
5. 给其中一个模型上传产物文件。
6. 检查上传后是否出现 **"分析中"** 状态徽标。
7. 等待分析完成，检查是否显示 **"已预分析"** 徽标 + **"重新分析"** 按钮。
8. 对另一个没有上传产物的模型，检查按钮是否显示 **"请先上传产物"** 且**不可点击**。
9. 模拟失败（如临时关闭 AI API 配置，或上传异常格式触发 4xx/5xx）后，检查该模型卡片内是否出现**持久红色错误条**；如不便模拟，请标记为"待真实异常时验证"。
10. 进入评估报告阶段。
11. 点击顶部 **"复制 MD"** 按钮。
12. 粘贴到任意文本编辑器，确认内容**只包含每个模型的 5 个模块**：
    - 产物效果反馈
    - 交付效率
    - 产物质量
    - 综合评价
    - 轨迹分析
13. 确认复制内容**不包含**：
    - 任务 prompt
    - 任务描述
    - 导出时间
    - 评分概览表
    - 验证说明
    - 系统调试信息
    - 原始 think / 思维链
14. 如果未上传正式产物效果截图，确认 **"产物效果反馈"** 不会编造，而是提示"未上传产物效果截图，暂无法填写产物效果反馈。"。
15. 如果未上传执行轨迹截图，确认 **"轨迹分析"** 显示 **"未提供轨迹截图。"**。

补充验收（可选）：
- 16. 确认历史"测试思路"阶段不会在 UI 出现（侧边栏只有 5 步：任务设计 / 任务信息 / 看板识别 / 产物分析 / 评估报告）。
- 17. 确认产物阶段顶部说明明确区分"产物文件"与"产物效果截图"。
- 18. 确认 StepReport 顶部副标题明确"我是测试者本人"视角。
- 19. 多模型并发时，每个模型的状态独立切换、错误条独立显示。
- 20. 删除某个模型后，其持久错误条不再出现在 UI 上。
